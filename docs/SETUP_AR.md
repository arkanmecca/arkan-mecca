# إعداد رحلة على Google Apps Script

## 1. إنشاء المشروع ونسخ الملفات

على حساب Google الذي سيملك المنظومة والبيانات، افتح [Google Apps Script](https://script.google.com/) وأنشئ مشروعاً جديداً باسم «رحلة — التسعير».

انقل الملفات من مجلد `dist/gas` في الحزمة:

| الملف | مكانه في محرر Apps Script |
|---|---|
| `Code.gs` | ملف نص برمجي باسم Code |
| `Store.gs` | ملف نص برمجي باسم Store |
| `Server.gs` | ملف نص برمجي باسم Server |
| `Index.html` | ملف HTML باسم Index |
| `appsscript.json` | ملف إعداد المشروع |

لنسخ المحتوى افتح الملفات بمحرر نصوص على الكمبيوتر. ملف Index.html يحتوي الواجهة المبنية كاملة؛ فتحه بالنقر يعرض واجهة غير متصلة، لذلك افتحه بمحرر نصوص لنسخ مصدره.

أظهر ملف `appsscript.json` من إعدادات المشروع، ثم ضع فيه محتوى الملف المرفق. يتضمن تفعيل الخدمة المتقدمة **Google Sheets API v4**. تأكد من ظهور خدمة Sheets ضمن خدمات المشروع، وإن طلب Google تفعيل Sheets API للمشروع السحابي المرتبط ففعّلها من إعداده الرسمي.

احفظ جميع الملفات. لا تضف ملفات خادم الاختبار أو مجلد test إلى Apps Script.

## 2. إعداد حساب المسؤول والبيانات

من **إعدادات المشروع → خصائص النص البرمجي / Script properties**، أضف:

| الخاصية | ما تضعه |
|---|---|
| `INITIAL_ADMIN_USER` | اسم دخول تختاره؛ حروف إنجليزية وأرقام ونقطة أو شرطة، 3 أحرف على الأقل |
| `INITIAL_ADMIN_PASSWORD` | كلمة مرور تختارها، بحد أقصى 72 بايت UTF-8. لا يوجد حد أدنى للطول في هذا الإصدار؛ اختر كلمة قوية بنفسك لأن الحماية الوحيدة الإضافية هي تقييد عدد محاولات الدخول |

لا توجد كلمة مرور إنتاج افتراضية في الحزمة، ولا تحتاج إرسال كلمة المرور في المحادثة.

شغّل الدالة `setup_` من محرر Apps Script، وراجع الأذونات المطلوبة على حساب المالك. تنشئ الدالة ملف Google Sheets خاصاً، ومجلداً خاصاً للنسخ الاحتياطية، وحساب المسؤول، وأنواع الغرف الأولية، وموعداً يومياً للنسخ والصيانة.

بعد نجاح الإعداد تحذف الدالة خاصيتي اسم الدخول وكلمة المرور الأولية. ستبقى الخاصيتان `DATABASE_ID` و`BACKUP_FOLDER_ID` لربط المنظومة بملفاتها. لا تغيّرهما أثناء الاستخدام العادي.

الإعداد لا يستورد أي بيانات من أركان ولا يضيف شركات تجريبية. الملفات الفعلية تبدأ فارغة، باستثناء حساب المسؤول والإعدادات وأنواع الغرف.

افتح مشاركة ملف البيانات ومجلد النسخ، وتأكد أنهما مقيدان. لا تشاركهما مع الشركات أو الموظفين الذين يجب أن يخضعوا لصلاحيات التطبيق.

## 3. التحقق الأولي والنشر التجريبي

شغّل `verifyInstallation_`. يجب أن يعرض سجل التنفيذ نجاح فحص البنية وكلمة المرور، وزمن عملية تجزئة كلمة المرور. هذا الفحص يعمل على حساب Google الحقيقي ويكمل الاختبارات المحلية المرفقة.

من **نشر → عملية نشر جديدة → تطبيق ويب**:

- التنفيذ باسم حساب المالك: **Execute as me**.
- الوصول إلى واجهة الويب: **Anyone**، بما يسمح لمن لا يملك حساب Google بفتح شاشة الدخول.

هذا الإعداد يتيح صفحة الدخول للزائر؛ الحصول على بيانات الشركات يظل مشروطاً بجلسة صحيحة وصلاحية يتحقق منها الخادم. لا تنشر ملف Sheets نفسه للعموم.

قد تمنع سياسة حساب Workspace النشر لمن لا يملك حساب Google؛ عندئذ يحتاج مالك الحساب مراجعة إعدادات المؤسسة، ولا يكفي تغيير كود التطبيق.

احتفظ بالرابط النهائي المنتهي بـ `/exec`. الرابط المنتهي بـ `/dev` للاختبار بواسطة محرري المشروع، وليس رابط الشركات.

افتح `/exec` من نافذة خاصة غير مسجلة في Google، وتأكد من ظهور شاشة اسم المستخدم وكلمة المرور الخاصة بالمنظومة.

## 4. خطوات الاستخدام الأولى

1. ادخل بحساب المسؤول، واضبط اسم المنشأة وأسعار الصرف.
2. أضف المدن والفنادق والخدمات، وراجع أنواع الغرف وأعداد الأشخاص.
3. أضف شركتين تجريبيتين، ثم حساب دخول لكل شركة. المستخدم يغيّر كلمة المرور الأولية عند دخوله.
4. أضف الموظفين، وحدد الصلاحيات المطلوبة لكل موظف. تعديل التسعير والتعريفات المالية يحتاج رؤية التكلفة.
5. أنشئ تسعيراً، واحسب نتائجه ثم احفظه.
6. أنشئ عرضاً من التسعير المحفوظ، ثم اعتمده.
7. افتح «نشر / عمولة»، واختر الشركات وحدد العمولات. راجع كل شركة والبنود والصافي ثم أكد النشر.
8. ادخل بحساب الشركة، وافتح العرض وأنشئ تسعيرة لعميلها وأضف تكاليفها وربحها.
9. راجع التسعيرة قبل الحفظ، ثم استخدم «نسخة العميل» للطباعة أو حفظ PDF، وExcel للتصدير.

## 5. قبول التشغيل على حساب Google

نفّذ الاختبارات التالية قبل إدخال بيانات العمل ودعوة الشركات:

- شركة أ ترى عروضها وتسعيراتها وحدها، وشركة ب ترى عروضها وحدها.
- المستخدم الموقوف والشركة الموقوفة لا يستطيعان متابعة جلسة سابقة.
- اختبر دخول المسؤول والموظف والشركة من هاتف وكمبيوتر ونافذة خاصة دون تسجيل Google.
- انشر البرنامج نفسه لعدة شركات بعمولة موحدة، واجعل لإحداها استثناء؛ تحقق من الصافي.
- عدّل عرضاً بعد حفظ تسعيرة للشركة؛ تحقق أن التسعيرة القديمة لم تتغير، ثم جرّب التحديث الاختياري.
- افتح السجل في نافذتين، واحفظ تعديلاً في كل منهما؛ يجب أن يرفض الحفظ القديم بعد نجاح الأول.
- جرّب عدة حسابات بالتزامن وقِس الاستجابة. حدود Apps Script تتعلق بطلبات التنفيذ وليس بعدد الشركات وحده.
- اختبر تنزيل Excel والطباعة وحفظ PDF على الأجهزة المستخدمة فعلياً.
- اختبر تسعيرة تحتوي خدمات بالدينار والدولار والريال وإجماليات منفصلة، وتكلفة إضافية بعملة أخرى مع سعر تحويل صريح.
- أنشئ نسخة احتياطية، واستعدها إلى ملف منفصل كما هو موضح أدناه، ثم افحص العروض والعمولات والتسعيرات.

لا تعتبر الفحص المحلي ضماناً لاختبار أذونات Google أو حصص التشغيل أو التحميل المتزامن في حسابك.

## 6. النسخ الاحتياطية والاستعادة

بعد الإعداد تُنشأ نسخة يومية قرابة الساعة الثانية صباحاً بتوقيت طرابلس؛ مواعيد محفزات Google تقريبية. يمكنك إنشاء نسخة إضافية من تبويب الإعدادات. النسخ تحتوي البيانات وكلمات المرور المجزأة، لذلك تبقى خاصة بالمالك.

لمراجعة استعادة نسخة:

1. خذ نسخة حديثة من قاعدة العمل الحالية.
2. من مجلد النسخ الخاص، حدد ملف النسخة المطلوب ومعرّفه.
3. أضف خاصية Script property باسم `RESTORE_BACKUP_ID` بقيمة معرف ذلك الملف.
4. شغّل `restoreBackup_` من المحرر. تفحص الدالة الروابط والبنية، وتُنشئ **ملفاً مستعاداً منفصلاً**، وتمسح جلساته القديمة.
5. افحص الملف المستعاد أو اربطه بنشر تجريبي مستقل. لا تستبدل قاعدة العمل قبل مراجعتها.
6. لاعتماد الاستعادة، أوقف استخدام المنظومة مؤقتاً، وغيّر `DATABASE_ID` إلى معرف النسخة المستعادة، مع الاحتفاظ بمعرف ونسخة القاعدة السابقة للرجوع.

عند الرجوع لنسخة قديمة تعود أسعارها وحساباتها وكلمات مرورها المجزأة أيضاً؛ تُلغى الجلسات القديمة ويُطلب تسجيل الدخول. راجع الحسابات التي كانت موقوفة أو كلمات المرور التي أعيد تعيينها بعد تاريخ النسخة.

لا تُحذف النسخ القديمة تلقائياً في هذه النسخة؛ راجع مساحة Drive واحتفظ بالنسخ التي تحتاجها.

## 7. تحديث البرنامج

خذ نسخة احتياطية، وحدّث ملفات الكود والواجهة من الإصدار الجديد، ثم حدّث عملية النشر إلى إصدار جديد. احتفظ بخصائص `DATABASE_ID` و`BACKUP_FOLDER_ID` وبعملية النشر نفسها. لا تشغّل `setup_` على قاعدة قائمة، ولا تستبدل البيانات بملفات الاختبار.

## 8. استيراد التعريفات من Excel

نزّل القالب من «التعريفات → قالب Excel». حافظ على اسم الورقة `Definitions` وأسماء الأعمدة:

| العمود | المعنى |
|---|---|
| `type` | `room` غرفة، `city` مدينة، `hotel` فندق، `service` خدمة |
| `name` | الاسم الكامل |
| `occupancy` | عدد الأشخاص للغرفة، من 1 إلى 20 |
| `extraBeds` | عدد الأسرّة الإضافية؛ فارغ للقاعدة الحالية |
| `cityId` | معرف مدينة قائمة للفندق، أو فارغ |
| `rate` | تكلفة الغرفة / الليلة بالريال للفندق |
| `cost` | تكلفة وحدة الخدمة |
| `currency` | `LYD` أو `USD` أو `SAR` |
| `saleCurrency` | عملة البيع الافتراضية للخدمة: `LYD` أو `USD` أو `SAR`؛ الفارغ يعني `LYD` |
| `unit` | `roomNight` للغرفة / الليلة، أو `item` للخدمة كاملة |
| `active` | `true` فعال أو `false` موقوف؛ الفارغ فعال |

استخدم قيماً مباشرة دون صيغ أو روابط. الحد 200 صف و2 ميجابايت في الدفعة. تظهر مراجعة قبل الاستيراد، ويُرفض تكرار الاسم والنوع. لا يستخدم هذا الاستيراد لاستعادة قاعدة البيانات كاملة.
